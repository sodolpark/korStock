06 · 가장 확실한 매도: 수익의 20% 되돌림

g(t) = 100 × (p(t) / average_entry_price − 1)        # 가격수익률, %
G(t) = 확인된 고점 가격의 가격수익률, %
F(t) = 0.80 × G(t)                                # 추정 수익 보호 기준
G = 2.95%  →  F = 2.36%
g = 2.04%  <  F = 2.36%  →  하방 유지 후 청산 후보

20%는 주가가 고점에서 20% 하락한다는 뜻이 아니라, 진입 후 확보한 이익의 20%를 돌려준다는 뜻으로 해석해야 거래 기록과 맞는다. +5% 고점이면 보호 기준은 +4%, +10% 고점이면 +8%다.

1번 거래 기준 이론상 고점은 약 146,704원, 보호 기준 가격은 약 145,863원이다. 기록상 실제 매도는 145,400원으로 기준을 약 463원 하회한다. 10초 하방 유지, 계산·주문 지연, 지정가 미체결, 기록 방식의 영향이 가능하다. 보호 기준 가격에 항상 체결되는 백테스트는 이 증거와도 맞지 않는다.

이 세 기능은 수익을 길게 가져가기 위해 “일시적 고가 체결 → 보호선 급상승 → 정상적인 눌림에 조기 매도”를 줄이려는 장치로 해석된다. 화면에 켜져 있다는 사실은 확인되지만 서로의 호출 순서는 미상이다.

  • 원시 최고가 H_raw, 검증 중 고가 H_candidate, 확정 고가 H_confirmed를 분리해 저장한다.
  • 제안: 후보 가격이 생긴 시점부터 가격이 후보의 99.9% 이상을 10초 연속 유지하면 후보를 확정한다. 후보 검증 중 더 높은 틱이 나와도 기존 타이머를 매번 재시작하지 않는다. 추가 고점은 다음 후보로 따로 검증한다.
  • 후보 하단 이탈·시세 불신·VI 발생 시 후보 확인과 연속 타이머를 초기화한다. 매수가·기존 확정 고점·기존 보호선은 보존한다.
  • “안정화 3봉·하락 비율 20%”는 원본 산식이 불명이다. 제안 버전에서는 1분 완성봉 3개를 사용해 비정상 고점 후보만 폐기한다. 확정 보호선을 낮추는 리셋은 사용하지 않는다.
  • 틱 이상치 15%의 기준값은 알 수 없다. 급락을 단순 삭제하면 손절도 사라질 수 있다. 의심 틱은 격리·호가 교차 확인 대상으로 삼고 실제 위험 관측은 유지한다.
  • ATR14를 1분 완성봉으로 쓰면 개장 직후 충분한 당일 표본이 없다. 전일 봉을 쓸지, 준비 완료까지 ATR 모드를 끌지 명시해야 한다. 화면에서 적응형은 OFF이므로 기본 재현에 ATR을 억지로 활성화하지 않는다.

08 · 추세와 호가 불균형의 AND 청산

두 번째 거래에 직접 기록된 조건은 추세 −20.39 < +0.05 및 불균형 −0.71 < −0.70이다. AND 체크와 일치한다. 다만 가중합 모드도 ON이므로 AND가 최종 결정인지, 가중 점수와 함께 쓰였는지는 아직 불명이다.

bad_trend = T_exit < threshold_T
bad_book  = I_exit < -0.70
bad_soft  = bad_trend AND bad_book
# 거래 기록 대조: threshold_T = 0.05
# 설정 화면 대조: threshold_T = 0.01
# 두 버전은 분리 저장하며 성과에 맞춰 사후 선택하지 않는다.

제안하는 호가 불균형 정의는 I=(B−A)/(B+A)이다. B와 A는 같은 거래소·동일 레벨 범위의 매수·매도 잔량이다. −0.70은 매도 잔량이 매수 잔량의 약 5.67배, −0.71은 약 5.90배에 해당한다. 화면 로그의 −32.2가 이 값의 100배라면 −0.322가 되지만, 이는 정규화 가설이다.

단순 잔량 비율은 호가 취소·이동을 반영한 이벤트 기반 OFI와 다르다. 원문은 “호가 불균형”이라고만 하므로 특정 논문의 OFI라고 단정하지 않는다. 매도 잔량이 크다고 항상 약세도 아니다. 잔량 흡수가 강한 상승과 공존할 수 있어 추세와 AND로 결합했을 가능성이 있다.

제안 버전에서는 5호가에 w=(1,0.8,0.6,0.4,0.2)를 적용하고 시간 가중 평균한다. 이것은 원본 수식이 아니다. 비교 대상으로 최우선 1호가, 10호가 단순합을 먼저 점검하되 같은 검증 구간에 맞춰 무제한 탐색하지 않는다.

추세는 단순 수익률, 회귀기울기, 회귀 t값, 가중 가격 변화 등 여러 식이 가능하다. 음수 −20.39만으로는 식별할 수 없다. 구현용 대안은 시간축을 분 단위로 한 log(중간호가)의 OLS 기울기 β를 구해 T=10,000β(bp/분)로 정의하는 것이다. 이때 +0.05는 bp/분이라는 새 의미이며 원본 임계값과 호환된다고 볼 수 없다. 따라서 제안 v1에서는 T<0을 사용하고, 원본 0.05/0.01은 대조 프로필에만 보존한다.

VI는 원칙적으로 2분간 단일가로 전환하는 장치다. 거래가 멎은 10초를 “하방이 10초 유지되었음”으로 세면 안 된다. 신규 진입을 중단하고 시장 상태가 정상으로 돌아온 뒤 유효 체결·호가로 지표를 다시 준비한다. 가격제한이나 거래정지에서는 손실한도 가격으로 청산할 수 없을 수 있다. [2]

일반 주권의 50,000~200,000원 구간 호가가격단위는 100원이다. 로그에 있는 153,850원은 일반 지정가 호가 격자와 다르므로 실제 체결가, 중간가격, 평균가격, 데이터 전사 중 무엇인지 확인해야 한다. 중간가호가 제도가 있으므로 숫자 하나만으로 잘못된 데이터라고 단정하지 않는다. 실행용 주문 가격은 선택 시장과 주문 유형에 맞춰 정규화한다. [3] [4]

KRX/NXT/통합 시세와 주문 목적지를 명시한다. KRX의 매수잔량과 NXT의 매도잔량을 임의로 섞어 단일 거래소 불균형처럼 계산하지 않는다. 중복 수신된 통합·개별 체결도 이중 집계하지 않는다. SOR 이용 여부와 시세 범위를 분리 기록한다. NXT의 존재와 최선집행 구조는 금융위 공식 자료로 확인된다. 이 재현 v1은 시장 혼합 문제를 줄이기 위해 KRX 정규 접속매매로 범위를 한정한 제안이다. [4]

  • 부분 매수 중 매도 조건이 생기면 남은 매수 주문 취소를 요청하고 확인한다. 이미 체결된 수량을 청산하되 취소 중 추가 체결도 수량에 반영한다. 계좌 전체 대사로 뒤늦게 생긴 잔량을 찾는다.
  • 매도는 실제 보유−기존 유효 매도 잔량 이내에서만 주문한다. 기본은 최우선 매수호가 수준의 시장성 지정가다. 하락 시 미체결 가능성을 고려해 2초마다 상태 확인, 취소 완료 후 재가격 또는 증권사 지원 주문으로 위험 축소한다.
  • 긴급 청산에서 시장가/시장성 지정가 중 지원 가능한 방식을 사전에 정한다. 가격 상한·하한과 VI·잔량 부재에서는 체결 보장이 없다. 주문 종류가 시장·세션마다 다를 수 있으므로 어댑터에서 검증한다.
  • 연결 단절은 보유 소멸이 아니다. 신규 진입 금지, 알려진 주문 식별자 보존, 재연결 후 미체결·당일 체결·잔고 순 대사, 차이 해소 전 재가동 금지.
  • 장 마감 청산 주문을 제출했다고 당일 위험이 0인 것은 아니다. 체결 확인과 잔고 0 확인까지 완료해야 한다. 거래정지 등으로 남으면 잔량을 사고 상태로 기록하고 운영자에게 표시한다.

한국투자증권 공식 Open API 저장소는 국내주식 시세·주문·잔고·WebSocket 관련 예제를 제공한다. 이는 구현 수단의 한 예이며 게시물의 사용 증권사를 특정하는 증거는 아니다. 실제 계정의 호출 제한·구독 제한·모의/실전 차이·지원 시장은 도입할 증권사 문서와 계정 조건으로 확인한다. 여기서는 고정된 API 요청 제한 숫자를 임의로 가정하지 않는다. [5]

16 · 수량과 계좌 손실한도

첨부의 수량 1은 전략의 포지션 크기를 설명하지 못한다. 무인 운용을 목표로 한다면 진입 규칙과 독립된 계좌 위험 한도가 필요하다. 아래는 수익성 검증 전 제안 시작값으로, 사용자의 자금·목표 수익을 가정한 맞춤 비중이 아니다.

E0 = 당일 시작 순자산
R_trade = 0.002 × E0                    # 거래당 계획 위험 0.2%
d = 0.015                              # 가격 손실 거리 1.5%
c = 왕복 예상 비용률 + 스트레스 슬리피지율 (계정별 입력)
q_risk = floor(R_trade / (P_entry × (d + c)))
q_name = floor(0.20 × E0 / P_entry)      # 종목 명목비중 상한 20%
q_liq  = floor(0.01 × 최근60초 실제 체결수량)
q = max(0, min(q_risk, q_name, q_liq, 주문가능수량))

전체 명목노출 상한 = 50% × E0; 최대 동시 종목 = 3
일일 중단 기준 = 순실현손익 + 실행가능가격 평가손익 ≤ −1.0% × E0
# 장중 입출금은 손익에서 분리. 수수료·세금도 포함.

20%와 50% 비중, 1% 거래량 참여, 0.2%/1% 위험 기준은 원본 수치가 아니다. q가 0이면 주문하지 않는다. 매수가격 급변·하한가·거래정지·유동성 고갈에서는 계획 위험을 넘을 수 있으므로 이 수식을 손실 보장으로 해석하지 않는다. 같은 테마 종목 간 상관도 별도 노출 한도로 관리한다.

19.2 틱 재생 시뮬레이터의 최소 요건

  • 의사결정 시점 t 이후 네트워크·계산·접수 지연을 적용한 t+latency 이후 데이터에서만 체결 가능성을 검사한다.
  • 매수는 해당 시점 ask 및 매도 잔량, 매도는 bid 및 매수 잔량을 소비한다. 수량을 호가 깊이에 따라 나누고 평균 체결가를 계산한다.
  • 수동 지정가 주문은 가격이 닿았다는 이유만으로 체결시키지 않는다. 대기열 선행 물량·이후 체결량·취소의 불확실성을 반영하거나 보수적 미체결 시나리오를 함께 제공한다.
  • 호가 스냅샷만 있으면 실제 대기열을 정확히 알 수 없다. 이 한계를 표시하고 체결 결과를 단일 확정치로 포장하지 않는다.
  • VI·거래정지·단일가·상한가/하한가·호가 비어 있음·수신 장애·중복 체결통보·취소 중 추가 체결을 이벤트로 재생한다.
  • 같은 미시 가격으로 신호를 만든 직후 그 가격에 지연 0·수량 무제한 체결을 허용하지 않는다.
  • 완성 전 분봉의 최종 고가·저가·종가, 양방향 이동평균, 이후 데이터로 복원한 이상치 필터, 수정 이후 종목 구성 등을 과거 의사결정에 사용하지 않는다.

19.3 과최적화 방지 설계

100개 테스트라는 설명만으로는 과최적화 검증이 되지 않는다. 급등 사례만 골랐거나 동일 데이터에 수십 개 청산 옵션을 반복 최적화했다면 성과가 부풀려질 수 있다. 무작위로 틱을 섞어 학습/검증을 나누지 말고 날짜·종목을 묶어 분리한다.

제안: 최소 여러 달의 날짜별 전 종목 후보 이력에서, 시간 순서대로 60% 개발·20% 검증·20% 최종 보류 구간을 둔다. 최대 특징창 360초와 포지션 보유 구간이 경계를 넘지 않게 purge한다. 매일 청산된 경우 날짜 블록 분할이 단순하다. 최종 구간을 한 번 본 뒤 수정하면 그 구간은 더 이상 최종 보류가 아니다. 다른 기간·종목으로 다시 검증해야 한다.

시작 실험은 4개로 제한한다: ① 단순 손실한도+시간 종료, ② +수익 트레일링, ③ +추세·불균형 AND, ④ +고점/하방 확인. 이후 적응창과 ATR을 각각 추가해 기여를 비교한다. 성과 좋은 설정을 많이 고른 경우 시도 횟수까지 기록하고 선택 편향을 보고한다. 원본 재현 목적의 산식 탐색은 성과 최적화와 별도 실험으로 관리한다.

평가 항목의미

“30%가 5% 이상 상방”은 관측 기준·시간 범위가 없는 주장이다. 설령 실제라 해도 +5%를 모두 실현하는 것도 아니다. 단순 예로 30%가 +5%, 70%가 −1.5%이면 비용 전 기대값은 +0.45%; 왕복비용 약 0.23%를 가정하면 약 +0.22%다. 승리 실현이 +3%면 비용 전 −0.15%, 동일 비용 후 약 −0.38%다. 이것은 구조를 설명하는 가정 계산이며 실제 승패 분포 추정이 아니다.

20 · 모의에서 실거래 후보로 넘어가는 기준

실거래 가능성을 위해서는 신호 성과와 운영 신뢰성 두 조건을 각각 충족해야 한다. 아래는 개발 완료 판정의 제안 기준이며 달성했다고 보고하는 내용이 아니다.

단계통과 조건
데이터·회귀 검증과거 미래값 참조 0건, 1주 거래 손익 계산 일치, 모든 단위 명시, 주문번호/체결번호 중복 처리 검증. 모순 데이터는 격리.
분리 백테스트보류 구간 비용 차감 기대값이 양수이고 날짜 블록 bootstrap의 95% 하한도 양수인지 확인. 표본 부족이면 보류. MDD가 사전 한도 이내.
비용·지연 스트레스기본 대비 총 거래비용 2배, 추가 불리한 1~2틱, 실측 지연 분포의 상위 구간을 적용. 결과를 모두 공개. 시세·체결 용량을 넘는 주문 제외.
실시간 그림자 운용제안 20거래일 이상 주문 없이 신호·예상 체결 기록. 백테스트와 실시간 신호 차이를 원인별 대사. 단순 20일 경과만으로 통과하지 않음.
주문 연동 검증모의환경에서 부분체결·취소 경합·응답 불명·재접속 복구·세션 마감 확인. 모의 체결이 실제 대기열을 재현하지 않는 한계를 분리.
제한된 실거래증권사 기능·운영 검증 후 최소 주문 크기, 최대 1포지션으로 시작. 미대사 잔고/중복 주문은 0건이어야 하며 실제 슬리피지 측정 후 단계적으로 재평가.

실시간 추론에 LLM이 꼭 필요한 구조는 아니다. AI는 로그 분석, 실패 거래 분류, 변경 후보 제안에 쓰고, 운영 엔진은 고정된 수식·설정으로 결정적으로 실행하는 편이 게시물의 설명과 맞는다. 다만 “모든 학습모델은 느려서 불가능”이라는 일반화는 근거가 없으며, 작은 수치 모델과 LLM의 지연은 구분해야 한다.
