# 구현 및 검증 상태

계획서에 따른 Python 프로젝트와 실행 경로를 구현했습니다. 수집, 원시 로그/Parquet, 인과적 재생, 연구 전략, 위험 예약, 주문/부분체결/취소, 계좌 대사, 명시적 복구, 운영 보고와 실전 전환 검사를 포함합니다. **실제 시장 데이터와 계좌 권한이 필요한 완료 조건은 별도 미완료로 남깁니다.**

## 실행한 검증

- `pytest`: **73개 통과**. 원본 64행 중 63행의 반올림 일치와 09:13:09의 20.6점 불일치를 그대로 검출합니다. 3건 거래의 산술과 2.95% → 2.36% 보호선을 검증했습니다.
- `ruff check`와 포맷 검사, `pip check`, wheel/sdist 빌드를 수행했습니다. Windows Python 3.13.15에서 실행했으며 Linux/3.12는 CI 구성을 추가했지만 이 세션에서 실행하지 않았습니다.
- 합성 로그 **3,783 이벤트**를 기록·재생·Parquet 변환했습니다. 진입·청산 완료 거래가 발생하고 종료 잔고/미체결은 없습니다.
- 같은 입력의 재생 신호 해시가 일치합니다. 최종 실제 해시와 파일 위치는 [검증 요약 JSON](validation-summary.json), 테스트 결과는 [JUnit XML](validation-tests.xml)에 있습니다.
- 비용 2배, 불리한 1/2틱, 1초 지연, 청산 모듈 제거, 고정창을 포함한 **8개 시나리오**를 실행했습니다. 합성 결과이므로 성과 자격은 모두 `UNVALIDATED`입니다.
- 기간 백테스트(2026-10-09 추가): `pytest` **78개 통과**(백테스트 5개 추가). 수집 형식의 합성 로그 253거래일로 기본 기간(2025-10-09~2026-10-08)을 실행해 일자 집계·누락 평일 8일 보고를 확인했습니다. 같은 변경에서 재생 경로를 최적화했으며, 변경 전 코드와 비교해 데모 8개 스트레스 시나리오와 무작위 10/30종목 흐름의 전체 보고서, 모든 지표 스냅숏이 동일했습니다. 30종목 무작위 158,769이벤트 재생은 215초에서 약 60초로 단축됐습니다. [검증 요약 JSON](validation-summary.json)의 코드 해시는 이 변경 이전 값입니다.
- 로컬 합성 부하: 30종목 31,200이벤트와 50종목 52,000이벤트. 원시 저장과 전략 처리를 포함한 측정입니다. 당시 수치와 실행 조건은 검증 요약 JSON에 보존했습니다. 실제 네트워크 수신 품질이나 거래소 체결 완전성 검증은 아닙니다.

테스트는 기본 HTTP 전송을 차단하고 명시적인 모형 전송만 허용합니다. 이 작업에서 실제 계좌 인증, 모의 계좌 주문, 실전 주문은 실행하지 않았습니다. 원본 연구 문서와 이미지는 보존했습니다.

## 외부 준비 후 이어갈 작업

1. 로컬 환경에 계정별 API 키를 공급하고 `probe`로 읽기 계약을 확인합니다.
2. 실제 거래일 일정·종목 상태·가격제한·비용을 입력하고 `collect`로 30종목을 수집합니다.
3. 실제 모의 주문으로 체결 통보, 취소 확인, 수수료 정산, 재접속 범위를 확인합니다. 체결번호 없는 REST 행은 추정 합산하지 않고 차이가 해소될 때까지 중단합니다.
4. 수집이 쌓이면 `backtest --stress`로 기간 성과와 스트레스를 날짜순 분리 평가하고, 최소 20거래일 shadow/replay 신호를 비교합니다. 키움은 과거 10호가를 제공하지 않으므로 1년 기간 평가는 1년간의 직접 수집(또는 동일 스키마로 변환한 외부 틱·호가 자료)이 필요합니다.
5. 사전 MDD 한도와 통계/운영 기준을 충족하면 검증 파일을 동결해 최초 1주 실행 품질을 확인합니다.

진입 산식의 원본 동일성, 실제 수익성, 실제 30/50종목 수집 안정성, 실계좌 복구 능력은 로컬 합성 시험만으로 완료 판정하지 않습니다. 조건검색의 기본 실행 통합, 자동 종목 분류, 수동 호가 대기열/종가 단일가 체결 모형은 자동으로 추정하지 않으며 현재 제공 범위는 [API 계약](../docs/API_CONTRACTS.md)과 [운영 절차](../docs/OPERATIONS.md)에 명시했습니다.
